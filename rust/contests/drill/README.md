# Drill — A 問題完答パターン練習

AtCoder の **A 問題で詰まらなくなる** ために、a-typeのよく出るパターンを詰め込んだドリル。  
a4 までやってみた感触（自力・写経）をもとに、**苦手分野を多めに**、**得意分野は確認程度に** 配分してある。

## 配分の意図（a1〜a4 のフィードバックより）

- ✅ できる: `input!`、`if/else`、`Vec` の読み込み、`.iter().min()/max()`
- ⚠️ あと一歩: 文字列スライス + parse（既出パターンの応用）
- 🟡 弱い: **`chars()` / `match` / イテレータ応用** / **エッジケース** / 出力フォーマット

→ 文字列を10問、`match` を4問、エッジケース系を3問。あとは桁操作・配列応用・偶奇/倍数/絶対値/階乗で全体を埋める。

## 取り組み方の提案

- **1日3〜5問** を目安に、テーマをまたいで解くと飽きない
- **詰まったら md のヒントを先に見る** → それでもダメなら写経 OK（A-4 のスタイルでよい）
- 解き終わったら **時間を空けて再挑戦**。再挑戦で何も見ずに通せたらマスター
- 苦手と感じたテーマは `notes/beginner/` に学びをまとめる

## 使い方

`src/bin/aN.rs` には `use proconio::input;` と空の `main()` だけのテンプレが用意されている。  
`cct aN` でサンプルテスト実行（例: `cct a5`）。

# Drill C — ABC C 問題 攻略ドリル（c1〜c12）

## 狙いと現状認識

AB は安定。**C を安定させて茶→緑**を目指すためのドリル。
abc461〜463 の実績（461C 未AC / 462C 自力AC=貪欲 / 463C は二分探索を写経）から、
**「どのテクニックを使うかに気づく力」と「気づいた後に Rust で書き切る力」**の両方を鍛える構成。

C で詰まる原因は次の 3 つに分かれる。解くたびに**どれで詰まったか**を記録すると伸びが速い。

1. **ロジックは分かるがコードが書けない** → 実装テンプレを体に入れる（c の実装明快な問題）
2. **テクニックに気づけない**（例：「ここで二分探索」「ソートしてこう持てば」）→ 各問の**認識トリガー**を覚える
3. **ロジックもコードも書ける** → 確認程度でOK

## 問題一覧（テクニック別）

| 番号 | テーマ | テクニック | 認識トリガー |
|---|---|---|---|
| c1 | ペアの差を最小に | 貪欲（ソート＋隣接） | 差/距離の合計を最小化＋自由に組める |
| c2 | 待ち時間の合計を最小に | 貪欲（SPT 昇順） | 完了時刻/待ち時間の合計を最小化 |
| c3 | x 以上の最小の要素 | 配列への二分探索 | ソート可＋同じ配列に何度も問い合わせ（=463C の型） |
| c4 | 荷物分割の最大負荷最小 | 答えで二分探索 | 最大を最小化＋「ある値で可能か」判定が簡単 |
| c5 | 同じ値のペアの数 | HashMap カウント | 出現回数を数える/同じ値の組 |
| c6 | 和が K になる 2 つ | HashSet（two-sum） | 和が K のペアの存在→相方 K-x を探す |
| c7 | 区間和クエリ | 累積和 | 区間の和を何度も聞かれる |
| c8 | 和が K の倍数の区間数 | 累積和＋余り＋カウント | 和が〜の区間数→「同じ値の組」に言い換え |
| c9 | 和が K 以下の最長区間 | 尺取り法 | 連続部分列＋条件以下の最長＋単調性 |
| c10 | 迷路の最短手数 | BFS（グリッド） | グリッド＋最短手数（重み1） |
| c11 | 連結成分の個数 | BFS/DFS（グラフ） | グループ分け/つながりのかたまりの数 |
| c12 | 区間加算の最大値 | いもす法（差分＋累積和） | 区間に一律加算が大量＋最後にまとめて見る |

優先順（実績ベース）: **c1,c2（貪欲・得意の強化）→ c3,c4（二分探索・写経からの自力化）→ c5〜c8（Map/累積和）→ c9（尺取り）→ c10,c11（BFS）→ c12**。

## 取り組み方（C 用）

各問は次の手順で。**ステップ3が認識力を一番伸ばす**。

1. 問題と**制約を読み**、テクニック仮説を立てる（30秒）
   - `N ≤ 10^9` → ループ不可（二分探索/数学）
   - `N ≤ 2×10^5` → `O(N log N)` まで（ソート/二分探索/尺取り）
   - `N ≤ 3000` → `O(N^2)` 全探索OK
   - 「最大化/最小化」→ 貪欲 or 答えで二分探索を疑う
2. **30分**自力で考える
3. 詰まったら md の**認識トリガーだけ**見る（コードは見ない）。それで書けるか試す
4. それでもダメなら md のコード片を写経 → **時間を空けて再挑戦**し、何も見ずに通せたらマスター
5. 「**何の情報でそのテクニックに気づくべきだったか**」を一言メモ（`notes/` 推奨）

`cct c1` でサンプルテスト（例: `cct c3`）。解答は `src/bin/cN.rs` に自分で書く。

## 仕上げ：本物の ABC C で「気づき」を試す

ドリルで型を入れたら、**判定機のある本物の C** で認識力を確認するのが最強。
[AtCoder Problems](https://kenkoooo.com/atcoder/#/table/) でユーザー名を入れ、ABC の C 列を上から埋めると未AC が一目で分かる。
