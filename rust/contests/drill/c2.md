# C-2: 待ち時間の合計を最小に

配点: 300点

### 問題文

$1$ 台の機械で $N$ 個のタスクを**順番に**処理する。タスク $i$ の処理には $T_i$ 単位時間かかる。  
あるタスクの「完了時刻」は、そのタスクが処理し終わるまでの累計時間である。

タスクを処理する順番を自由に決められるとき、**全タスクの完了時刻の合計**を最小化し、その最小値を出力せよ。

### 制約

- $1 \le N \le 2 \times 10^5$
- $1 \le T_i \le 10^9$
- 入力は全て整数

### 入力

```
N
T_1 T_2 ... T_N
```

### 出力

完了時刻の合計の最小値を出力せよ。

---

### 入力例1

```
3
3 1 2
```

### 出力例1

```
10
```

`[1,2,3]` の順に処理すると完了時刻は $1, 3, 6$ で合計 $10$。これより小さくはできない。

---

### 入力例2

```
1
100
```

### 出力例2

```
100
```

---

### 入力例3

```
4
4 3 2 1
```

### 出力例3

```
20
```

`[1,2,3,4]` で完了時刻 $1,3,6,10$、合計 $20$。

---

### 練習ポイント（貪欲：気づきにくい「昇順」）

完了時刻の合計は「短いタスクを先にやる」と小さくなる。理由：先に置いたタスクの時間は、**後ろの全タスクの完了時刻に足され続ける**から、影響の大きい（後ろに何度も足される）先頭ほど短くしたい。

これが **SPT（Shortest Processing Time）順**。交換論法で「隣り合う 2 つを入れ替えて損しない順 = 昇順」と示せる。

認識トリガー: **「完了時刻／待ち時間の合計を最小化」→ 処理時間の昇順ソート**。
こういう「何でソートすればいいか」がパッと出ないのが C で詰まる典型。手を動かして小さい例で確かめる癖をつけると見抜けるようになる。

合計は $10^{14}$ 級になるので **`i64`**。累計（acc）と総和（sum）の 2 変数を回すだけ。
