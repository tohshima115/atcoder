## 問題へのリンク

[ABC462 C - Not Covered Points](https://atcoder.jp/contests/abc462/tasks/abc462_c)

## 問題の要約

平面上の N 点（X, Y はそれぞれ 1..N の順列）。左下 (0,0)・右上 (Xᵢ,Yᵢ) の長方形の**内部（辺上を含まない）**に他の点を1つも含まない i の個数を求める。

## 方針 — 2次元をソートで1次元に落とす（O(N log N)）

点 i が条件を満たす ⇔ **自分より X も Y も小さい点が1つも存在しない**。
= 左下から見た**パレート最前線（階段状フロンティア）に乗っている点**の数。

この言い換えができれば、あとは1軸をソートで固定してもう1軸だけの問題にできる:

- **Y昇順にソート**すると、走査中「これまで見た点は全部 Y が自分より小さい」が保証される。
- 残る判定は X だけ。**これまでの X の最小値より小さい = 自分を覆う点はいない = 新記録更新**。

## 実装アプローチ（コンテスト提出版 / きれいに書けた）

```rust
use proconio::input;

fn main() {
    input! {
        n: usize,
        mut point: [(i64, i64); n],
    }
    let mut cnt: i64 = 0;
    let mut min_x: i64 = i64::MAX;
    point.sort_by_key(|&(_, y)| y);   // Y昇順
    for &(x, _y) in &point {
        if x <= min_x {               // X が新記録 → 覆う点なし
            cnt += 1;
            min_x = x;
        }
    }
    println!("{}", cnt);
}
```

検算（例1）: 点 (2,1)(1,3)(3,2) を Y昇順 → (2,1)(3,2)(1,3)。
min_x: 2(採用)→3(却下)→1(採用) で **2**。一致。

## このセッションで学んだこと

### 2次元条件を「ソート + 1パス最小値追跡」に落とす型

「X も Y も小さい点が無いか」のような**2軸の支配関係**は、片方をソートで順序固定すると、もう片方の最小値（or 最大値）追跡だけで判定できる1次元問題になる。パレート最前線・階段状フロンティアを数える典型。C問題で頻出。

知識レベル: 🟢 実装可能

---

### 等号 `<=` が `<` と同じになる理由は「制約」に効いている

`if x <= min_x` で正しいのは **X が順列（重複なし）だから**。X に重複があり得る問題だと `<=` と `<` で答えが変わる。「なぜ等号込みで大丈夫か」を制約に紐づけて意識しておくと、似た問題で踏み外さない。

知識レベル: 🔵 説明可能

---

### `i64::MAX` は import 不要（`std::i64::MAX` は非推奨）

コンテスト中はコピペで `use std::{i64::MAX};` を使ったが、これは古い書き方:

- モジュール定数 `std::i64::MAX` は **soft-deprecated**（補完で非推奨警告が出る）。
- 今は**関連定数 `i64::MAX` を import なしで直接使える**。1行目ごと削除して `let mut min_x: i64 = i64::MAX;` でOK。

> 運用メモ: コンテスト中は警告無視で通すのが正解。振り返りで直せばよい。

知識レベル: 🟢 実装可能

---

### `sort_by_key` で意図を出す

```rust
point.sort_by(|(_, a), (_, b)| a.cmp(b));  // 動くが冗長
point.sort_by_key(|&(_, y)| y);            // 「Yで昇順」が一目でわかる
```

動作は同じ。キー1個で順序が決まるなら `sort_by_key`、複雑な比較なら `sort_by`。([[sort-cmp-ordering]])

知識レベル: 🟢 実装可能
