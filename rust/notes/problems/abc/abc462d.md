## 問題へのリンク

[ABC462 D - Accomplice](https://atcoder.jp/contests/abc462/tasks/abc462_d)

## 問題の要約

各人 i は時刻 [Sᵢ, Tᵢ] に館にいる。犯行は整数時刻 x に始まり D 単位かけて x+D に終わる。犯人ちょうど2人が x〜x+D の間ずっと館にいた。（2人, 開始時刻 x）の組が何通りあるか。

## 方針（O(N + T_max)）

人 i が開始時刻 x の犯行に参加できる条件は `Sᵢ ≤ x` かつ `x + D ≤ Tᵢ`、つまり

```
x ∈ [Sᵢ, Tᵢ − D]   （両端含む、ただし Tᵢ − D ≥ Sᵢ のときのみ）
```

各開始時刻 x について「参加できる人数 c(x)」を imos（差分配列＋累積和）で求め、その中から2人を選ぶ通り数 **C(c, 2) = c(c−1)/2** を全時刻ぶん足す。

ペアを全列挙すると O(N²) = 4×10¹⁰ で即TLE。**「2人組を1つずつ数えず、時刻ごとの人数からまとめて数える」**ことで N に対し線形になるのが肝。座標が 10⁶ と小さいので配列 imos が素直で速い（イベントソートの O(N log N) 別解より単純）。

## 実装アプローチ（修正版）

セッション中の初稿は方針◎だが実装バグが4つあった（下記）。修正後の骨子:

```rust
use proconio::input;

fn main() {
    input! {
        n: usize,
        d: usize,
        time: [(usize, usize); n],
    }
    const T: usize = 1_000_002;
    let mut diff = vec![0i64; T];

    for &(s, t) in &time {
        if t >= s + d {            // Tᵢ − D ≥ Sᵢ のときだけ
            diff[s] += 1;
            diff[t - d + 1] -= 1;  // 区間 [s, t-d] に +1 → 右端は t-d+1 で戻す
        }
    }
    // 累積和で各時刻の人数 c(x)
    for i in 1..T {
        diff[i] += diff[i - 1];
    }
    let mut ans: i64 = 0;
    for &c in &diff {
        ans += c * (c - 1) / 2;    // C(c,2)
    }
    println!("{}", ans);
}
```

## このセッションで学んだこと

### 「2人選ぶ」は公式一発 C(c,2) = c(c−1)/2

組み合わせといっても2人を選ぶだけなので、階乗もパスカルの三角形もMODも不要。各時刻の人数 c から `c*(c-1)/2` を足すだけ。

知識レベル: 🔵 説明可能

---

### imos（差分配列）の off-by-one

区間 **[l, r]（両端含む）** に +1 したいときの差分は:

```rust
diff[l]     += 1;
diff[r + 1] -= 1;   // ← 右端は r ではなく r+1 で戻す
```

初稿は `diff[t-d] -= 1` としていて、`x = t-d` の分が消えていた。「右端の1つ先で −1」を徹底する。

知識レベル: 🟢 実装可能

---

### 初稿にあった4つのバグ（自分の癖の記録）

1. **配列サイズの取り違え**: `diff` の添字は *時刻*（最大10⁶）なのに `vec![0; n]`（最大2×10⁵）にしていた → 範囲外。サイズは座標の上限に合わせる。
2. **imos の右端 off-by-one**: 上記。`t-d` ではなく `t-d+1`。
3. **累積和ループの underflow**: `for i in 0..n { diff[i] += diff[i-1] }` は i=0 で `i-1` が usize underflow でパニック。`1..` から回す。ループ範囲も `n` でなく時刻上限。
4. **負区間ガード漏れ**: 館滞在が D 未満（`t-d < s`）の人は有効な x がない。ガードしないと `-1` が `+1` より前に来て imos が壊れる。`t - d` を usize で計算すると `t < d` で underflow もするので `if t >= s + d` で判定。

知識レベル: 🟢 実装可能

---

### オーバーフロー

c は最大 2×10⁵、`c(c-1)/2` ≈ 2×10¹⁰、それを 10⁶ 時刻ぶん合算すると最大 ~10¹⁶ 規模。`i32` では溢れるので `ans` も途中計算も `i64`（[[integer-types-overflow]] の 10⁹ ルール）。入力例3がまさにオーバーフロー確認ケース。

知識レベル: 🔵 説明可能
