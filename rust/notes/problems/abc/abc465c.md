## 問題へのリンク

[ABC465 C - Reverse Permutation](https://atcoder.jp/contests/abc465/tasks/abc465_c)

## 問題の要約

$A=(1,2,\ldots,N)$ に対し $k=1,2,\ldots,N$ の順に「$S_k=$`o` なら先頭 $k$ 項を反転」する。全操作後の $A$ を求める。$N \le 5\times10^5$。

## 方針

### 提出版（TLE）

毎回 `a[0..=i].reverse()` を実際に実行。`o` が続くと反転コストが $1+2+\cdots+N = O(N^2)$ で TLE。

```rust
for i in 1..n {
    if str[i] == 'x' {
    } else {
        a[0..=i].reverse();   // ここが毎回 O(k)
    }
}
```

方針の方向（「$O(N^2)$ になってる」の自覚）は合っていた。落とし所は「reverse を実際にやらない」。

### 改善版（O(N)）: deque + 向きフラグ

**キーになる構造**：操作 $k$ の反転長はちょうど $k$ で、$k$ は $1,2,\ldots,N$ と**単調増加**する。つまり後の反転ほど長い先頭を反転し、前の反転範囲を丸ごと含む（入れ子で伸びる）。

すると「先頭 $k$ 項全体を反転」＝**今まで並べた列の向きを逆にするだけ**。実際に reverse せず**向きフラグを反転**すればよい。

- 新しい値 $k$ は「今の列の論理的な末尾」に加わる
  - 正順なら `push_back(k)` / 逆順なら `push_front(k)`
- `S_k=='o'` なら**フラグを反転**するだけ

最後にフラグが正順ならそのまま、逆順なら反転して出力。各ステップ $O(1)$、全体 $O(N)$。

```rust
use std::collections::VecDeque;
let mut dq: VecDeque<usize> = VecDeque::new();
let mut flip = false;
for k in 1..=n {
    if flip { dq.push_front(k); } else { dq.push_back(k); }
    if s[k - 1] == b'o' { flip = !flip; }
}
let mut ans: Vec<usize> = dq.into_iter().collect();
if flip { ans.reverse(); }
```

入力例1（`ooxoo`）で検算：`[1]→[2,1]→[2,1,3]→[2,1,3,4]→[5,2,1,3,4]` で `5 2 1 3 4` ✓

## このセッションで学んだこと

### reverse 系は「実際にひっくり返さず、向きフラグ + 両端キューで管理」

全体 reverse を繰り返す操作は、物理的に配列を反転せず **bool 1個（正順/逆順）と `VecDeque` の front/back** で表せる。「論理的な末尾」がフラグによって物理的な先頭にも末尾にもなる、というのがポイント。文字列・数列操作で頻出の定石。

**知識レベル: 🟡 雰囲気理解** — 今回の1問で型として認識できた。次に reverse 繰り返し系を見て反射で「フラグで持てる?」と出せるか要確認。

### 操作の本質を「何を変えて何を変えないか」で分解する

全体反転は**順番を逆にするだけで中身の相対順序は保つ**。この「変わるもの／変わらないもの」の切り分けができると「物理的に動かさず状態だけ持つ」に到達できる。TLE を見たときの反射的な問い：

1. この操作、毎回やる必要ある?（遅延・記号化できない?）
2. 操作の列に規則性ない?（今回は「反転長が単調増加」）

**知識レベル: 🟡 雰囲気理解**

### 「累積 → パリティ → 状態」の2段変換

自力では「これまでに `o` が何回出たか記録する配列」までは着想できていた（＝正解ルートの一歩手前）。足りなかったのは最後のジャンプ：

- ステップ $k$ で要素を前/後ろどちらに置くかのフラグ **＝ それまでの `o` の個数の偶奇（パリティ）**
- `o` 偶数回 → 正順 `push_back` / 奇数回 → 逆順 `push_front`

累積した情報を**値としてどう足すか**ではなく、**偶奇 → 向き（状態）に効かせる**と気づけばよかった。「累積 → パリティ → ON/OFF・向き・位置」という変換の型は bit/スイッチ系で頻出。関連：[[../../topics/bit-operations]]

**知識レベル: 🟡 雰囲気理解** — 着想の芽はあったので、「累積は値以外（状態）にも効く」を引き出しに追加。

### （補足）deque を使わない別解：両端2ポインタ

「答えの各位置に何が来るか」を両端から2ポインタで詰めても解ける（deque + フラグと本質は同じ）。今回は VecDeque + フラグが一番素直。
