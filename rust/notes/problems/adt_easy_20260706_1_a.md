## 問題へのリンク

ADT easy 2026-07-06 (1) A — 文字列 $S$ の $a$ 文字目と $b$ 文字目を入れ替えて出力。$2 \le |S| \le 10$、$1 \le a < b \le |S|$、英小文字のみ。

## 問題の要約

指定した2箇所の文字を入れ替えるだけ。

## 方針

### 提出版（AC）

一時変数で退避してから入れ替え。

```rust
let mut chars: Vec<char> = s.chars().collect();
let sa = chars[a - 1];
let sb = chars[b - 1];
chars[a - 1] = sb;
chars[b - 1] = sa;
```

### 改善版：スライスの `.swap()`

2要素の入れ替えは一時変数を書かず `.swap(i, j)` 一行で済む。

```rust
let mut chars: Vec<char> = s.chars().collect();
chars.swap(a - 1, b - 1);
let ans: String = chars.iter().collect();
println!("{}", ans);
```

### 別解：`Bytes` で受けて `Vec<u8>` を swap

英小文字だけなので proconio の `Bytes` マーカーで最初から `Vec<u8>` として受け取れる。`char` 版より変換が減る。

```rust
use proconio::marker::Bytes;
input! { s: Bytes, a: usize, b: usize }
let mut s = s;
s.swap(a - 1, b - 1);
println!("{}", String::from_utf8(s).unwrap());
```

## このセッションで学んだこと

### スライス/Vec の `.swap(i, j)` で2要素を安全に入れ替え

一時変数で退避（`sa`/`sb`）しなくても、`v.swap(i, j)` が2つの要素を同時に交換してくれる。

なぜ一時変数が要ると感じるか？ `v[i] = v[j]` と直接代入すると、片方を上書きした瞬間に元の値が消えてしまうから。`swap` は「両方の値を同時に扱う」処理をライブラリ側が担保してくれる。配列要素の入れ替え全般で使える定番メソッド。関連：[[../reference/vec-slice-operations]]

**知識レベル: 🟢 実装可能** — 使いどころ（2箇所の交換）がはっきりしているので反射で出せる。

### `String` は添字アクセスできない → 一度は列に変換が必要

Rust の `String` は中身が UTF-8 バイト列で、`s[2]` のような添字アクセスができない仕様。文字が1バイトとは限らない（日本語など）ため「n文字目」を定数時間で取り出せないから。よって `String` に `.swap()` は生えていない。

「n文字目を入れ替え」をするには、添字アクセスできる `Vec<char>` か `Vec<u8>` に**一度変換するのは避けられない**。

- `Vec<char>`：どんな文字でも安全・汎用的
- `Vec<u8>`（`Bytes`）：ASCII 限定だが変換が減り、競プロでは定番

関連：[[../topics/string-char-conversion]]

**知識レベル: 🔵 説明可能** — なぜ添字不可か（可変長 UTF-8）まで説明できる。

### proconio の `Bytes` マーカー

`use proconio::marker::Bytes;` して `input! { s: Bytes }` と書くと、文字列を最初から `Vec<u8>` で受け取れる。出力に戻すときは `String::from_utf8(s).unwrap()`。ASCII 前提の文字列問題で `chars().collect()` を省ける。

**知識レベル: 🟡 雰囲気理解** — 存在と使い方は把握。`Chars` など他マーカーとの使い分けは要整理。
