## 問題

[[../../../contests/drill/c1|問題文]]

$2N$ 個の数を自由に2個ずつのペアに分ける。各ペアの差の合計を最小にしたときの値を出力する。

## 実装アプローチ

**認識トリガー**: 「差・距離の合計を最小化」＋「自由に組み合わせ」→ **ソートして隣どうしをペアにする貪欲**。

ソート後、隣接する2つ（`a[0]`と`a[1]`、`a[2]`と`a[3]`、…）を組むと差の合計が最小になる。
合計は最大 $10^{14}$ になりうるので `i64`。

### 最初に書いたコード（添字を 2倍＋1 で計算）

```rust
a.sort();
let mut sum: i64 = 0;
for i in 0..(n / 2) {
    sum += a[i*2 + 1] - a[i*2];
}
println!("{}", sum);
```

動くし正しい。`0..(n/2)` で回すので `n` が奇数でも安全という利点はある。
ただし `a[i*2+1]` という添字計算がやや読みにくい。

### 改善案（n が偶数なので chunks が一番きれい）

```rust
a.sort();
let ans: i64 = a.chunks(2).map(|p| p[1] - p[0]).sum();
println!("{}", ans);
```

`mut sum` を使わず、「2個ずつ切り出して → 差をとって → 合計」と宣言的に書ける。
この問題は **N が偶数（必ずペアになる）保証あり** なので chunks 版が最適。

## このセッションで学んだこと

### 「2ずつ進む／2個ずつ区切る」の3つの書き方

| 道具 | 何をする | 例 |
|---|---|---|
| `i*2`, `i*2+1` | 添字を手計算 | `a[i*2+1] - a[i*2]` |
| `(0..n).step_by(2)` | インデックスを2ずつ進める | `for i in (0..n).step_by(2) { a[i+1]-a[i] }` |
| `a.chunks(2)` | 2要素のスライスを順に返す | `a.chunks(2).map(\|p\| p[1]-p[0])` |

#### `step_by`

```rust
for i in (0..n).step_by(2) {   // 0, 2, 4, ...
    sum += a[i + 1] - a[i];    // i*2+1 の手計算が消える
}
```

⚠️ `n` が奇数だと最後の `i = n-1` で `a[i+1]` が範囲外 → panic。偶数保証がいる。

🟢 実装可能

#### `chunks(2)`

`[a[0],a[1]], [a[2],a[3]], …` という「2個ずつのスライス」を順に返す。
「2個ずつのペア」という意図がそのままコードに出るのが利点。

```rust
let ans: i64 = a.chunks(2).map(|p| p[1] - p[0]).sum();
```

⚠️ こちらも `n` 奇数だと最後のチャンクが1要素になり `p[1]` で panic。
似た仲間に `windows(2)`（1ずつずらして隣接ペアを全部見る）がある。配列を区切る系で何度も使えるので両方おさえておく。→ [[../../topics/iterator-catalog|iterator-catalog]]

### `for` + `mut sum` より `.map().sum()`

可変変数に足し込むより、「変換して合計」を `.map().sum()` で宣言的に書くのが Rust の定石。
今回のように「各要素 → 1つの数 → 全部足す」形はそのまま `.map(...).sum()` にできる。

```rust
let ans: i64 = a.chunks(2).map(|p| p[1] - p[0]).sum();
```

`sum()` は型注釈（`let ans: i64`）かターボフィッシュ（`.sum::<i64>()`）で型を明示する必要がある点に注意。→ [[../../topics/sum-collect-turbofish|sum-collect-turbofish]]

🟢 実装可能
