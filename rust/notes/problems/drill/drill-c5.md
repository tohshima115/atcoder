## 問題

[[../../../contests/drill/c5|問題文]]

$N$ 個の整数 $A_1, \ldots, A_N$ から、$i<j$ かつ $A_i = A_j$ を満たす組 $(i,j)$ の個数を求める。

## 実装アプローチ

**認識トリガー**: 「同じ値が何個あるか」を数えて、その個数から答えを作る → **HashMap で出現回数をカウント**。

値ごとに出現回数 $c$ を数えれば、その値から作れるペアは $\binom{c}{2} = \dfrac{c(c-1)}{2}$。
それを全ての値について足し合わせれば答え。値域が $10^9$ と広く配列では数えられないので **HashMap** を使う。

### 提出したコード

```rust
let mut cnt: HashMap<i64, i64> = HashMap::new();
for &x in &a {
    *cnt.entry(x).or_insert(0) += 1;
}
let ans: i64 = cnt.values().map(|&c| c * (c-1) / 2).sum();
println!("{}", ans);
```

計算量は $O(N)$（HashMap の挿入・更新が平均 $O(1)$）。

## このセッションで学んだこと

### HashMap は「ラベル付きの辞書」

配列が「**添字（0,1,2…固定）→ 値**」なのに対し、HashMap は「**好きなキー → 値**」の対応表。

```
配列 a:     0→3, 1→3, 2→7      (添字は連番で固定)
HashMap:    3→2, 7→1, 100→5    (キーは任意・とびとびでOK)
```

- `HashMap<i64, i64>` ＝「キー i64、値 i64」。**1キーにつき1値**（同じキーは上書き）
- 「2次元」ではなく「キーの型が整数じゃなくてもいい一列の辞書」というイメージ
- 今回は `キー=Aの値そのもの, 値=その出現回数`
- 値域が広い($10^9$)とき、配列だと巨大すぎて確保できない → HashMap が活きる場面

### `entry(x).or_insert(0)` ＋ `*… += 1` のカウントイディオム

「初出なら0で作る、既出ならその値を取り出す、どちらでも +1 したい」を1行で書く定番。

```rust
*cnt.entry(x).or_insert(0) += 1;
```

- `entry(x)` … キー `x` の場所（エントリ）を指す
- `.or_insert(0)` … **キーがあれば既存値への `&mut`、なければ 0 を入れてから `&mut`** を返す
- 先頭の `*` … 返ってきた **可変参照の中身**を +1 する（`*` を忘れると「参照そのものに+1」でエラー）

初回 `0→1`、2回目以降 `今の値→+1` が、これ1行で処理できるのがミソ。

🟡 雰囲気理解

### `.keys()` / `.values()` / `.iter()` の使い分け

| メソッド | 取れるもの |
|---|---|
| `.keys()` | キーだけ |
| `.values()` | 値だけ |
| `.iter()` | `(&key, &value)` のペア |

今回は出現回数（値）だけ要るので `.values()`。

```rust
let ans: i64 = cnt.values().map(|&c| c * (c-1) / 2).sum();
```

⚠️ **HashMap は順番が保証されない**（入れた順でも昇順でもない）。
合計など順序に依存しない処理なら問題なし。順番が必要なら別途ソートするか `BTreeMap` を使う。

🟡 雰囲気理解

---

### 各値の寄与 → 全体で合計、というパターン

「組の総数」を直接数えず、**値ごとの組数 $\binom{c}{2}$ を出して足す**。
`map(|&c| c*(c-1)/2)` で各値の寄与に変換し、`.sum()` で集約する流れ。
[[drill-c2]] の「寄与を足す」発想と同じ。

🟢 実装可能
