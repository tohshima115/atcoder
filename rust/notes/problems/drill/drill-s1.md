## 問題

[[2d-grid-drill]] の S1。H×W 整数グリッドで、Q 個の矩形 (r1,c1,r2,c2)（1始まり）の**矩形和**を出力。機構は ④ 2次元累積和（[[2d-grid-and-prefix]]）。

---

## 提出したコード（2パス構築）

```rust
let mut g_sum = vec![vec![0i64; w+1]; h+1];   // +1サイズの番兵
for i in 1..=h { for j in 1..=w { g_sum[i][j]  = g_sum[i][j-1] + g[i-1][j-1]; } }  // 横に積む
for j in 1..=w { for i in 1..=h { g_sum[i][j] += g_sum[i-1][j]; } }                 // 縦に積む
for &(r1, c1, r2, c2) in &q_set {
    let ans = g_sum[r2][c2] - g_sum[r1-1][c2] - g_sum[r2][c1-1] + g_sum[r1-1][c1-1];
    println!("{}", ans);
}
```

サンプル一致（12 / 28）。**一発で正解**。累積和の作り方がきれいだった。

---

## このセッションで学んだこと

### クエリの4項は包除原理（理解は固まっている）

`g_sum[r2][c2] - g_sum[r1-1][c2] - g_sum[r2][c1-1] + g_sum[r1-1][c1-1]`

- 全体から「上の帯」「左の帯」を引くと、**左上の領域を2回引いてしまう** → 最後に足し戻す。
- `|A∪B| = |A| + |B| − |A∩B|` のベン図と構造が同じ。

🔵 説明可能（自分の言葉でベン図に結びつけられた）

### +1サイズの番兵で `r1-1` が0行/0列に逃げる

`vec![vec![0; w+1]; h+1]` で 0 行目・0 列目を全0に。`r1=1` でも `g_sum[r1-1]=g_sum[0]=0` になり**添字が負にならない**。G4 のパディングと同じ発想がここでも効く。

🟢 実装可能

### ★ 構築とクエリは「同じ包除の4項」（今日の収穫）

2次元累積和は **作るときも引くときも、符号だけ違う同じ4項**。1パス漸化式で書くとそれが一目で見える：

```rust
// 構築（1パス版）: + + + −
g_sum[i][j] = g[i-1][j-1] + g_sum[i-1][j] + g_sum[i][j-1] - g_sum[i-1][j-1];
// クエリ:            + − − +
```

自分は **2パス（横→縦）** で書いた。1パス漸化式は理解はできたが「思いつけない」状態。
→ 計算量はどちらも O(HW) で**全く同じ**（全マス1回読むのが下限なのでこれより速くは作れない）。
→ **本番は手が覚えてる2パスでOK。** ただし「構築=クエリの対称」は脳に焼く価値がある。

🟡 雰囲気理解（1パス漸化式は読めるが、まだ自力で書き起こせない）

## このセッションの収穫

- 包除のクエリ4項を**自分の言葉**（引きすぎた左上を足し戻す＝ベン図）で説明できた。
- **構築とクエリが同じ4項構造**だと気づいた。1パス vs 2パスは計算量同じ、好みで選ぶ。
- 番兵 +1 サイズで境界（`r1-1`）を吸収する手筋が G4 → S1 で一貫。
