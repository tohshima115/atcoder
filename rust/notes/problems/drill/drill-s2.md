## 問題

[[2d-grid-drill]] の S2。H×W 整数グリッドと整数 k。**すべての k×k 正方形の和の最大値**。機構は ④（各窓を2次元累積和で O(1)）。

---

## 提出したコード

```rust
let mut g_sum = vec![vec![0i64; w+1]; h+1];
for i in 1..=h {
    for j in 1..=w {
        // ★ 1パス漸化式を自力で書けた（drill-s1 で🟡だった所）
        g_sum[i][j] = g[i-1][j-1] + g_sum[i][j-1] + g_sum[i-1][j] - g_sum[i-1][j-1];
    }
}
let mut ans = i64::MIN;                 // ← 修正後（最初は 0 にしてバグった）
for i in 0..=h-k {
    for j in 0..=w-k {
        let window = g_sum[i+k][j+k] - g_sum[i+k][j] - g_sum[i][j+k] + g_sum[i][j];
        ans = ans.max(window);
    }
}
println!("{}", ans);
```

サンプル一致（28）、負ケース `-1 -2 / -3 -4`, k=1 → `-1` も一致。

---

## このセッションで学んだこと

### ★ max/min の初期値バグ（今日の本命）

最初 `let mut ans = 0;` で書いて、**全マスが負のグリッドで `0` を返した**。

- `ans.max(window)` を回すとき、初期値 0 は「和が0の窓が存在する」と嘘をついているのと同じ。
- 全窓が負だと、実在しない 0 が勝ち残ってしまう。
- 競プロ頻出の **「max/min の初期値」バグ**。最大値を求めるなら初期値は「ありえないほど小さい値」から始める。

```rust
let mut ans = i64::MIN;   // max を取るなら MIN から
// （min を取るなら i64::MAX から）
```

**`i64::MIN` 初期化が安全な条件 = 候補が必ず1つ以上ある**こと。今回は `k ≤ h, k ≤ w` で窓は最低1個 → `max` が1回は呼ばれ MIN は必ず上書きされる。候補0個の可能性がある問題では MIN がそのまま出るので注意。

この罠は累積和に限らず「最大値/最小値を求める」全部で効く。サンプルが正の数だけだと**すり抜ける**ので、負の入力を自分で1つ作って試す癖をつける。

🔵 説明可能

### 1パス漸化式が自力で書けた

drill-s1 では2パスで書き、1パス漸化式は🟡（読めるが書けない）だった。今回は最初から1パスで構築 → `+ + + −` の符号も正しく書けた。

🟢 実装可能（drill-s1 の🟡から昇格）

### 窓ループの範囲と usize アンダーフロー

- 窓の左上が取れる範囲は `i in 0..=h-k`, `j in 0..=w-k`（`=` を含むのを忘れない）。
- ⚠️ `h-k` は `k > h` のとき **usize アンダーフローで panic**。今回は制約上 `k ≤ h` なので実害なしだが、`usize` の引き算は常にこのリスクがあると意識する。

🟢 実装可能

## このセッションの収穫

- **max/min の初期値は MIN/MAX から**（0 初期化は負が来ると死ぬ）。サンプルが正だけだとすり抜けるので**負ケースを自作してテスト**。
- 1パス累積和漸化式が🟡→🟢に昇格（s1 の学びを即適用）。
- `usize` の引き算（`h-k`）は常にアンダーフローを意識。
